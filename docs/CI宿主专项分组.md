# CI 宿主专项分组

`check-ddns-authority.sh` 保留无参数或四个运行时路径的完整串行入口。前置 `--group` 支持下表六个独立组，以及 `all`、旧版 `receipts` 组合入口；组合入口仍只准备一次运行时，保持原串行顺序，无遗漏或重复。无效组或多余参数在准备前退出，任一准备/专项失败立即停止，不回落到其他组。

| CI宿主组 | 专项 | 场景数 |
| --- | --- | --- |
| authority | Lua授权、RPC授权 | 8+11 |
| tasks | Lua任务、RPC任务、Lua明确维护、RPC明确维护 | 7+10+8+11 |

| receipts-huawei | 华为云真实任务、Lua原回执归档、RPC原回执归档 | 4+6+10 |

六组共18个业务脚本、135个场景，拆组不增加或重复计算验收成果。各组检出同一提交、准备固定依赖/运行时并验证私有隔离，组内仍串行。CI仅运行六个独立组，不选择完整receipts组合。原source全部检查和13组extended保留，SDK仍等待source/extended/native全部成功；各任务25分钟、HTTP/单场景超时、业务开关与私有namespace不变。

r108按已保存的本地成功日志核对：原receipts四家合计测试主体2232.359秒，已超过单任务25分钟，且未计准备依赖/运行时。拆分后Cloudflare532.798秒、Aliyun546.497秒、DNSPod558.580秒、华为云594.484秒；授权197.977秒、任务/维护263.180秒。以上是历史本地时间，排除依赖准备与运行时构建，不代表GitHub实际用时或超时保证；实际CI结论单独核对。

`scripts/ci-native-groups-regressions.py` 以真实POSIX shell执行实际入口，用临时Python调用记录器验证：六组分区18脚本；完整旧入口顺序；每组及组合入口的含空格路径；非法输入零执行；每个专项失败阻断；各组准备失败阻断；语法/LF；旧receipts串行顺序；组合失败不进入后续供应商。共9项调度合同，不替代原135个业务运行时场景。下一CI执行原业务回归，普通调度修改不重复已经通过且未变的业务代码。
