# CI 宿主专项分组

`check-ddns-authority.sh` 保留无参数或四个运行时路径的完整串行入口，另支持前置 `--group authority|tasks|receipts|all`。无效组或多余参数在准备依赖前退出；任一准备或回归失败即停止本组，不能回落到其他组。

| 宿主组 | 原检查脚本 | 场景数 |
| --- | --- | --- |
| authority | Lua授权、RPC授权 | 8+11 |
| tasks | Lua任务、RPC任务、Lua明确维护、RPC明确维护 | 7+10+8+11 |
| receipts | 原供应商任务、Lua原回执归档、RPC原回执归档 | 4+6+10 |

三组共9个脚本、75个既有场景，分组不新增或重复计算业务验收成果。各组独立检出同一提交，复用固定扩展依赖、ucode/rpcd/HTTP/Lua准备顺序与私有隔离前置，组内保持串行。工作流新增独立native矩阵，原13组extended和source原检查保留；native任一组失败也会阻止SDK构建。每个CI任务仍为25分钟，原HTTP/单场景超时及业务开关不变。

历史本地测试主体合计约994秒，尚不包含准备依赖、运行时构建或原UI协议回归，不能据此声称GitHub实际耗时或保证不会超时。CI实际耗时及结论以之后的完整运行记录为准。该调整只分散调度压力，不关闭私有namespace、不共享宿主网络、不增加自动轮询。

`scripts/ci-native-groups-regressions.py` 以真实POSIX shell执行实际入口，在临时目录用记录器代替Python子进程，验证九脚本分区、旧入口顺序、路径含空格、非法输入无执行、每个脚本失败后的阻断、准备失败阻断和Shell语法。它验证调度与失败传播，不代替原75个运行时场景；原业务验证结果分别保留，完整远端回归仍需CI。

第10步结束只登记本地结果；下一轮单独投递CI。投递后立即结束，用户发“核对CI结果”时才查询一次；CI诊断、修复和重投不计开发步骤，整轮成功核对后才进入下一周期。
