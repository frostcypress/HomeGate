# DDNS 单规则同步与持久结果

在来源绑定的 WAN6 计划之上，内部 `homegate-ddns-read.sh --sync RULE_ID --confirm` 连接四家已有供应商 worker。入口及共用 DNS 协调器的 `ddns_sync_enabled=false` 均关闭；原来的计划、读取、记录、持久回执和终态门禁也必须分别满足。生产 Makefile 不安装该原型。本阶段仅实现手动确认的一条 AAAA/auto 规则；冻结 CLI `ddns-sync [rule-id]` 的正式授权、全批调度及生产启用仍待接入。

## 从计划到固定请求

规则和地址不能由调用者任意拼接。入口先按《[DDNS计划与WAN6采样.md](DDNS计划与WAN6采样.md)》完成一次 WAN6 采样，并保留 frontend/supervisor 锁。派发前再在配置锁内重新核对原配置字节、迁移代及私有快照，重新提取 HGDDNSINTENT1；把同一个规则 ID 和已采样地址重建成规范 HGDDNSPLAN1，逐项比较整份私有计划。代次、账户、供应商、规则、来源、地址、请求、额外字段或启用意图不一致时拒绝，不传递原调用者的地址、URL、端点、RecordId 或 TTL。

仅重建成功的 ready 规则产生规范 `upsert/ddns/resource/value`，通过 0600 私有文件及 stdin 传给固定协调器。账户和供应商来自已重建计划，供应商只能是 cloudflare/aliyun/dnspod/huaweicloud 四个固定分支。禁用规则保留只读预检结果，不采样或写 DNS；不支持的来源、IPv4、无地址或无效规则同样止于预检阶段。预检未执行写入时仍使用 ddns-plan 响应，实际派发结果使用 ddns-sync 响应。

共用协调器增加独立关闭的内部别名 `--ddns-sync-internal PROVIDER ACCOUNT --records`，强制当前原配置绑定及该供应商持久回执、终态功能已开启。它复用经 inode/属主/权限核实的 frontend 和 supervisor 锁描述符；不会重新打开同一个 supervisor 锁造成自锁。普通 DNS 调用仍自行打开并持有自己的描述符。这个别名是内部 root 协调接口，不能作为 LuCI/RPC 的直接用户输入接口；未来正式写入口仍须履行授权和确认合同。

## 供应商结果和持久屏障

读取、记录决策、传输、变更前持久检查点、变更后核对及终态发布全部沿用现有供应商实现。AAAA 相同值不重复写，不创建变更检查点；变化只操作该规则绑定的记录。创建或更新的原成功字节必须与持久 `dns-operation/terminal` 相同，才可输出 confirmed。缺失、篡改、不完整或错误范围的结果不能冒充成功。

DDNS 适配器重建规范供应商 JSON，核对供应商、账户、配置代次、退出码、错误、效果及单规则计数。只接受 created/updated/unchanged；删除和批量计数不能混作本次 upsert 成功。对外只给规则 ID、供应商、代次、结果、效果及脱敏错误，不给地址、域名、设备或凭据。`write_ready:false` 表明没有据此授予后续写入权限。

确认成功也保留供应商持久屏障，必须经现有供应商的明确确认归档接口处理，不自动归档、解除或退役。变更请求发出后失败仍为 unknown，retryable:false，原 DNS 工作和 DDNS 外层目录均保留，下一同步被阻止；相同值的观察不能自动补造原操作成功。不能根据一次超时推断云端没有发生变更。调用者或清理阶段中断也保守保留可疑工作。

## 本阶段边界

只对已绑定的初次迁移代做手动单规则同步。HGDDNSINTENT1 本身不是服务启用授权，导入/迁移候选默认禁用语义不变。本接口不启动服务，不提供周期或事件调度，不接受全批写入，也不自动收集 DDNS 外层孤立目录。未来须补齐正常运行配置与启用权限、外层恢复/明确收集、批量结果和规则隔离、状态/退避，再进入正式业务接管。当前代码不可据此安装替换旧生产插件。

回归使用实际 BusyBox、Lua、curl/签名及供应商 worker，访问一次性本地 TLS 数据库；“云端已变更但响应失败”由夹具模拟，不能当真实供应商、目标 ABI、实机重启/资源或完整 M07/M08 通过。详细日志与设备记录仅本地，必要源码、协议及回归脚本可进入公开清单。

新任务的外层来源记录与明确收集见《[DDNS外层工作恢复与确认收集.md](DDNS外层工作恢复与确认收集.md)》。本页原r61缺少归属记录的目录仍不追认；新内部派发别名增加原外层JOB参数，并须满足新增工作门禁。
