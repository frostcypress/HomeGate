# DDNS 外层工作恢复与确认收集

本阶段为已确认的单规则 DDNS 工作增加来源记录和可续作的明确收集。`ddns_work_enabled=false` 在 DDNS 入口、共用 DNS 协调器和固定收集工具三处关闭；生产 Makefile 不安装原型。没有自动清理、重新写 DNS、自动归档或把观察结果补作成功。

## 派发前记录归属

新同步必须同时满足原有预检、执行及新增工作门禁。已重新绑定配置和计划后，原进程在 `.ddns-plan-JOB/binding` 原子发布 HGDDNSWORK1：存储身份、原 boot、配置代次、规则/供应商/账户、外层 PID 与启动 tick、目录设备/inode、配置代 manifest 和四个固定输入成员 SHA256。记录本身规范 LF、带完整校验和、0600；写入及目录 fsync 后才可派发。记录不含凭据。已有同任务收集计划或不完整临时记录会阻止派发。

内部协调器核实真实父 PID、借用的两把锁和完整来源记录。DDNS 内部别名携带原外层 JOB，供应商沿用该任务号，故持久回执和 `.dns-check-JOB` 与外层任务明确对应；普通供应商调用继续使用自身任务号。原进程退出、PID 被复用、来源成员变化或绑定失败时不能继续派发。

## 明确收集及中断续作

内部入口 `homegate-ddns-read.sh --collect-work ORIGINAL_JOB --confirm` 只接受安全数字任务号及明确确认，不接受路径。工具持有共用 frontend/supervisor 锁，拒绝原 PID 仍活跃或已复用，不发信号；须处于原 boot、原存储身份及当前同一迁移代。

首次收集先检查完整七成员和全部权限、链接、长度、SHA、目录 inode。通过现有恢复快照重新证明原配置字节和私有代，再重建规则计划与请求；供应商冻结上下文用现有 restore 函数重新绑定，请求必须与外层完全相同。原成功结果还须等于有效持久 terminal，terminal-meta、检查点、任务号和代次须由既有供应商恢复检查核实。unknown、只有当前地址一致、缺失终态或其他任务的成功均不能授权收集。

确认后在同一私有运行目录发布 HGDDNSCOLLECT1：绑定完整来源记录、terminal-meta 和待清理结果哈希。完整校验、文件/目录同步及原子改名之后，才逐个处理 provider/public/input/plan/intent/result/binding 七个固定成员，binding 最后移除。没有递归删除，不处理未知成员；所有剩余成员先通过全量检查再开始删除。

中断后仅凭有效既有计划接受已经删除的成员；重新核实 boot、身份、代次、原配置、持久终态、剩余哈希及原目录 inode，才继续剩余固定操作。完整 `.next` 可在重新核验后发布，残缺/重复/损坏计划保留并拒绝。工作目录已删且原持久回执仍有效时重复确认幂等；收集计划保留为该任务的本地记录，不能借用它处理复用 PID 下的新目录。

## 与供应商恢复的边界

成功响应固定 `outer_collected:true/effect:none/write_ready:false`。仅收集 DDNS 外层临时工作，原 DNS 工作、持久回执、终态和写屏障保持原样；供应商工作收集与归档仍须使用其已有的明确确认操作。收集器没有云 API，也不自动解除 unknown、重试写入或生成原成功。

r61 及更早外层目录缺少 HGDDNSWORK1，不追认归属，不补造记录，继续保留并阻塞。预检中断或新绑定发布前失败导致证据不完整，同样保留。本阶段只续作已有完整证据的已确认收集；不覆盖断电后丢失的 RAM 目录或跨 boot 推断。正常运行配置/启用授权、全批调度、正式 UI/生命周期及实机验收仍待接入。

验证使用真实 ash、Lua、供应商 worker 与私有本地 TLS 数据库，覆盖四家已确认/unknown/额外文件/部分删除及故障边界。模拟 boot/PID/文件系统故障不是实际设备重启或断电证据。详细日志、设备及宿主记录仅本地，必要源码和本协议按公开清单保留。
