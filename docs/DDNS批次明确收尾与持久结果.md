# DDNS 批次明确收尾与持久结果原型

r71 本地专项完成，生产门禁保持关闭，不安装到正式包。

`homegate-ddns-batch.sh sync --confirm` 保留 r70 行为。新增 `sync --confirm-closeouts` 是独立的明确同意：仅对本次固定批次产生并验证的原始 confirmed 成功回执，调用既有收集和退役协议，再执行下一条规则。预存归档、收集记录或历史结果均拒绝开始；unknown 结果保留原始屏障，不参与收尾。

私有 `dns-batch-results` 最多保存 32 条发生 confirmed 变更的规则的原始供应商回执、原始 DDNS 结果、原始证据哈希和退役证明。记录与设备、代次、授权、修订、启动和父进程绑定，采用规范 JSON 和 SHA256 帧，600 单链接，持有共同双锁。公开输出只显示规则、供应商和状态。

先持久归档原始回执，再发布 recorded 行，随后退役归档，最后发布 closed 行。存在未闭合行或发布暂存时，即使功能门禁关闭，普通写入仍被阻止。`homegate-ddns-batch-results.sh recover --confirm` 仅恢复已验证的发布和原有收尾；没有 DNS 写入路径。`status` 返回脱敏历史，`forget --confirm` 仅在记录全部闭合且现有写守卫允许时删除历史；下一批不能自动覆盖历史。

归档与首条结果发布之间中断时，原始归档仍存在；若没有有效结果暂存，须使用既有明确收尾入口处理，不能推断或补造结果。损坏、异机、异任务或不匹配的暂存不会自动丢弃。无变更及失败结果仍按原 HGDDNSSTATE1 保存；此历史专门留存已明确收尾的原始成功证据，不是完整批次报告。状态缓存、结果历史和全局 DNS 日志各有职责；历史不能授权重放成功写入。

新增4静态/21非root运行、受影响20静态/14运行、2root及11工程检查通过；不代表 CI、真实云账户、目标 ABI、安装包或设备验收通过。正式调度和生产生命周期尚未接入。
