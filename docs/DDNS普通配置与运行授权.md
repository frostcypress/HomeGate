# DDNS 普通配置与运行授权

本阶段增加普通配置代的独立 DDNS 授权与私有快照接口。配置引擎及固定授权工具的 `ddns_authority_enabled=false` 均关闭，生产 Makefile 不安装原型。它不启动服务、不写 DNS，尚未连接自动 DDNS 调度、正式 UI 或生产生命周期。

## 普通配置来源

原来的备份解析、导入、迁移及恢复候选保持默认禁用。新引擎只读命令 `runtime-ddns-snapshot-read` 要求持久命名空间、新授权门禁和既有生产投影门禁；当前代须有已绑定的 `source.conf`，固定 `/etc/config/homegate` 须私有且逐字节等于当前 `public.conf`。使用现有完整事务校验、源基线检查及 HGPRIVATE1 帧，不另建配置库或解析器。

普通配置必须完成现有预览/确认和受观察的服务停止、配置投影及应用日志收尾。仅私有代提交、旧迁移副本、尚未发布或应用中状态不够。总开关仍为禁用的备份候选，不会因存在一个旧迁移的 enabled 字段或某个调用者布尔值而自动生效。

## 一次性明确授权

内部 root 工具 `homegate-ddns-authority.sh preview RULE_ID` 仅选择当前代中存在的 AAAA/auto 规则，核对其供应商及所需私有凭据槽存在。Cloudflare 要求 secret，Aliyun/DNSPod 要求 key_id+secret，华为云另要求 account_id；这是缺凭据检查，不是远端认证成功声明。返回一次性 confirmation、规则/供应商、代次及 300 秒期限，不授予运行权限。

`commit CONFIRMATION` 在相同 frontend/supervisor 锁下重新验证当前来源，校验预览所属 boot、单调时间、存储身份、当前代完整 manifest、公开配置摘要、规则和旧授权摘要。旧令牌、替换/取消的预览、配置或凭据改变、来源改变、过期或其他 boot 的确认全部拒绝。确认成功才在私有存储中发布 HGDDNSAUTH1；它不是 UCI 主服务开关，也没有调用 start/enable。

授权仅限该规则的 DDNS；未选中的规则没有许可，证书、代理和访问控制不由此开启。确认操作将来只能由经过服务端授权的正式 UI/业务适配器调用；此 root 原型没有新的 Web/RPC 路由。正常保存后的代次、恢复/导入的新代、凭据更换、来源不匹配都会使旧授权不可用；不存在自动续用到新代的规则。

## 持久化、检查与撤销

HGDDNSAUTH1 绑定 enabled/disabled 状态、身份摘要、配置代及 manifest/源配置摘要、所选规则、令牌、签发 boot/单调时间和前一个授权摘要，带规范 LF 和校验和。预览文件、授权文件及固定暂存文件均为 0600、单链接；文件及目录 fsync 后原子 rename 并再次同步。没有把凭据或域名写进授权记录或公共响应。

完整未发布暂存只能在相同有效确认下明确续作；不完整或不同内容拒绝，存在授权暂存时运行检查失败。已改名但同步失败的相同授权可在明确重试时重新同步，成功收尾后原确认不能再用。检查也须成功同步有效授权及目录，才报告 authorized:true；不把一次命令失败或遗留文件猜作已授权。

`check` 重新验证当前配置来源和完整授权。`snapshot` 另要求私有 FD3 管道和 FD4 普通文件，验证完整帧后分别写出同代 HGPRIVATE1 和 HGDDNSINTENT1：配置正文仍默认禁用，只有所选规则的私有运行意图为 1。公共响应不含帧、凭据、摘要或授权令牌。后续运行读取端必须使用这一受验证接口，不能直接取文件中的 enabled 字符串。

`revoke --confirm` 原子发布 disabled 墓碑，不恢复为旧授权。它可以在同一锁内丢弃该工具的有界未完成授权暂存，再安全缩小许可；失败继续拒绝运行检查。`cancel --confirm` 只移除有界的惰性预览文件，不撤销现有有效授权。两者都不启动/停止服务，也不写 DNS。

已生效的授权作为持久意图保留；启动后仍须重新核对命名空间、代次、来源、凭据和屏障。确认票据不能跨 boot 使用。模拟 boot 下的重验不代表设备断电或真实冷启动已验收；正式冷启动协调、旧写入口共锁和所有业务接管仍待完成。

## 本阶段边界

### 有界多规则授权（r69）

`preview-rules RULE_A,RULE_B` 为同一已发布普通配置中的 2～32 个规则建立一次确认；不接受通配符、空项、重复、路径或外部输入。标识沿用 64 字节上限，集合规范排序且不超过 2079 字节。任一成员不存在、不为 AAAA/auto 或缺少供应商所需凭据时整份预览拒绝，不部分授予。四家供应商可在同一集合中；响应只列规则标识，`provider:multiple` 表示集合，不能当成第五种供应商派发。

多规则使用 `HGDDNSAUTH2`，与原单规则 `HGDDNSAUTH1` 共用同一个 active/pending/暂存位置、确认票据、共锁、代次/来源/凭据和旧授权摘要绑定。记录仍为规范 LF、固定字段和校验和；仅集合行改为排序且唯一的逗号列表，文件总长限 4096 字节。HGDDNSAUTH1 不能装入集合，HGDDNSAUTH2 不接受单项或非规范顺序。每次确认替换整个集合，不自动合并已有许可；通过原 `preview RULE_ID` 可明确缩小为单规则，撤销覆盖整份集合。

新增独立 `ddns_multi_authority_enabled=false`。关闭它会阻止多规则预览、确认和有效性检查，但仍允许显式撤销已有有效格式记录；环境变量不能开启门禁。原授权门禁仍须开启，生产配方不安装原型。

`check-rule RULE_ID` 检查集合成员。`snapshot` 为后续全批计划输出整个授权集合的 HGDDNSINTENT1；新增 `snapshot-rule RULE_ID` 在重新验证整份集合后，仅将已授权的所选规则置为 1，其余规则置为 0。普通单规则入口使用后者，原始工作归属、派发及中断收集仍按单规则精确绑定，不能把整个集合意图当作某一笔历史请求。完整配置、主服务和其他业务保持默认禁用，未选规则没有许可。

此项完成授权与既有单规则执行/显式收尾的衔接；全批执行、单次采样后的逐规则派发、状态隔离和正式调度仍待接入。持久回执仍阻止后续写入，未知操作不能自动重试，也不因获得多个规则许可而自动归档或退役。

普通配置的授权现已连接固定单规则执行及只读恢复，旧迁移原型入口继续单独保留。后续仍须补全批同步、状态/退避及正式 UI/生命周期。主服务、开机启停、其他业务授权和资源预算没有由本模块定义或宣称通过。

测试在私有 Linux 配置/服务夹具内运行真实 ash、Lua、fsync、rename 和 flock；没有修改目标路由器、访问真实云服务或启动生产服务。详细环境和验证记录仅本地保留；必要源码、协议和回归按公开清单管理。

## 普通配置的单规则执行与只读恢复

`homegate-ddns-read.sh --runtime RULE_ID` 为已授权单规则生成只读计划；`--runtime-sync RULE_ID --confirm` 明确执行。入口、协调器、外层工作工具及持久检查点工具的 `ddns_runtime_enabled=false` 都保持关闭。普通入口先在 frontend/supervisor 共锁下核实选定规则授权，才建立工作目录及采样；不会使用旧迁移 enabled 字段代替授权。调用者不能传地址、域名、供应商请求或端点。

计划及派发前均从 r63 的授权 snapshot 接口获取 HGPRIVATE1 和单规则 HGDDNSINTENT1；同一批仍只采样一次。协调器通过固定 `--ddns-runtime-sync-internal` 分支核实原父 PID、HGDDNSWORK2 归属、选定规则和当前有效授权，再用普通已发布来源快照调用原供应商 worker。共锁一直保留，授权或配置修改不能插入其间。四供应商协议、变更前检查点及原始成功终态沿用既有实现。检查点按当前代是否存在 source.conf 固定选择普通或迁移来源；普通来源另需关闭中的门禁，不通过“某次读取失败后换另一种来源”回退。

HGDDNSWORK2 与旧 HGDDNSWORK1 分开识别，其他字段和规范校验沿用原有外层工作合同；普通分支不能接纳旧迁移来源，迁移分支也不能把普通工作接过去。已确认外层工作仍通过 `--collect-work ORIGINAL_JOB --confirm` 明确收集，重建普通来源及选定规则的完整意图、计划、请求和供应商 context，保留 DNS 持久回执与写屏障。未知、缺失证据不清理，完整收集计划的中断续作继续逐项检查。

root 内部协调器的 `--runtime-reconcile-internal PROVIDER ACCOUNT ORIGINAL_JOB --confirm` 仅允许既有持久回执的只读 reconcile。固定引擎 `runtime-ddns-recovery-snapshot-read` 只在 DNS 存在屏障中开放读取；应用日志、其他未完成事务和源配置保护不放宽。它要求当前普通投影配置逐字节匹配、代次和私有数据有效，并使用原供应商恢复函数重新绑定原请求及冻结 context。该入口没有 collect、repair、retire 或记录写入选项。

只读恢复不要求当前写授权仍有效，已撤销意图或授权文件暂不可读不影响核实历史操作；它也不会由此授予写权限。当前配置或凭据已改变、原任务/账户不符、证据损坏则拒绝。普通写路径仍须当前明确授权。恢复观察只报告原请求当前状态，不把 desired-present 或已消失的目标改写成原始成功，不补造 terminal、不重试写入、不归档或解除屏障。模拟授权撤销及本地进程退出不代表目标设备真实重启或断电证据。

## r70 全批协调衔接

当前授权集合已接入一次明确调用的有界全批协调，复用单次采样、单规则执行及原状态/退避；持久回执仍全局阻止后续写入。协议见 [DDNS全批协调与共享采样](DDNS全批协调与共享采样.md)。自动调度、正式CLI/UI及生产生命周期仍未接入，原型门禁保持关闭。
