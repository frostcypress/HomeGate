# DDNS 本地状态与退避

本阶段提供 root 内部 `homegate-ddns-state.sh status RULE_ID`、`sync RULE_ID --confirm` 和 `reset RULE_ID --confirm`。`ddns_state_enabled=false` 固定门禁关闭，生产配方不安装；原四供应商、普通来源、授权及持久结果门禁仍各自生效。它连接 r64 单规则执行，为后续批次协调提供等待判断，没有新增常驻任务、定时器或自动重试。既有原型入口保留，不宣称生产入口已全面接管。

## 查询与运行

状态查询使用普通已发布配置的恢复读取接口，核实当前代、规则/供应商、必要凭据槽及配置间隔。它不访问云 API、不采样 WAN6、不创建缓存目录。当前写授权只有在共锁和既有写守卫可核实时才标为 true；无法核实不猜测已获授权。查询本身始终 `effect:none, write_ready:false`。`last_effect` 只是同来源同 boot 缓存中的历史结果，不表示本次查询改变 DNS，也不是新的远端核实结论。

`status` 查询成功退出0；`sync` 遇等待、暂停、未授权或屏障时返回规范状态并退出4，不采样或请求云端。真正执行后沿用原规范响应及0/1退出码；无效输入或内部证据错误不伪装成规则成功。

运行入口保留 frontend/supervisor 共锁，先检查当前普通来源、授权、原有 DNS/应用/工作屏障及本地等待状态，才调用固定 `--runtime-sync RULE_ID --confirm`。原入口只增加按 inode/属主/权限验证的锁借用，不重新打开导致自锁。它再次按原规则验证来源和授权，现有供应商 worker 继续负责变更前持久检查点、变更后核对及原始终态。包装层不能替代原守卫或批准任意地址/域名/请求。

## 有界缓存及发布

缓存仅在 `/var/run/homegate/ddns-state/` 保存。每条规则一个 HGDDNSSTATE1 canonical JSON，单链接0600，最多4096字节；目录0700。字段只有存储身份/当前代 manifest 摘要、boot、代次、规则/供应商、间隔、单调时间、连续失败数、延迟、结果、错误类别及历史 effect；不保存凭据、域名、IP、设备、请求或响应正文。

只接受规则文件及对应 `.RULE.next`、`.RULE.result` 两类固定暂存，单项不超过65536字节，总目录包括暂存最多192项；写前预留两项暂存空间，新规则另预留一项记录空间，最多190条历史记录。未知成员、链接、权限/长度异常、非 canonical 帧、另一条规则的记录拒绝且保留原字节。旧来源/boot的已完成历史标为 stale，公共结果不把旧历史冒称当前来源结果。残缺暂存保留并阻止该规则自动继续。

派发前先原子发布 inflight 缓存：文件/目录同步后 rename，再同步已发布文件和目录，成功后才执行原入口。调用者中断、未知退出、无效报告或发布失败不能推断为未写入或成功；保留 inflight/暂存和既有证据。子进程仍继承共锁，原独立监督约束供应商进程族。缓存不是持久 DNS 回执，不能替代原检查点和终态。

结束时严格重建并核对原 canonical ddns-sync 或单规则 ddns-plan 响应，才更新缓存。未知字段、规则/供应商/代次/退出码不符、伪造成功、extra响应拒绝。缓存发布失败不抹掉实际变更或原回执，也不重发写入。对外只在安全收尾后返回原规范响应，不反射未知数据。

## 等待与退避

- 创建/更新确认成功或当前值无需写入：连续失败数归0，至少等待当前配置 `ddns_interval` 秒。
- 明确无写入的网络不可用、临时错误、超时或限速：连续失败数最大8，延迟为 `max(ddns_interval, min(3600, 60 × 2^(失败数−1)))` 秒。长于一小时的配置间隔仍予遵守；不从供应商任意响应接受调用者可控延迟。
- 认证、请求、配置或不支持等非重试错误：paused，不按时间自动变成可执行。
- inflight 或 unknown：需要明确恢复，不因时间过去或重建状态缓存而自动重试；持久/同 boot 屏障继续优先阻止写入。
- 同 boot 的单调时间倒退：clock_invalid，拒绝执行。已完成历史来源/boot变化后可在新来源/当前授权和全部守卫核实通过时重新形成新状态；旧 inflight/unknown 不凭来源变化推断已结束。

“可到期”只表示此缓存不要求继续等待，不授予写权限；下一次仍需明确调用、当前授权和全部守卫通过。生产周期调度、全批结果隔离、多规则许可与正式CLI/UI仍待接入。

## 明确重置

`reset RULE_ID --confirm` 只移除该规则三个固定缓存文件。它要求当前普通来源有效（已删除规则的旧缓存也可明确清理，不要求重新授予该规则运行许可）、共锁可持有、既有 writer-check 和 DNS/外层工作存在屏障全部通过；任何实际 DNS 未决/未归档记录或工作残留仍阻止重置。只对有界私有普通文件操作，不递归删除。

它不修改配置或授权、不删除/归档原DNS回执、不补造成功、不解除持久屏障、不访问云端，也不会立刻执行DNS。若只是缓存发布前中断且原执行证据证明无未决操作，用户可明确重置等待历史再自行选择执行；不能将它用于绕过未知远端变更。

测试沿用现有 Linux、BusyBox/Lua、真实 flock/fsync/rename 及本地回环 TLS 供应商夹具。模拟时钟/boot或注入失败不是设备真实重启、断电和资源验收；目标 ABI、正式三包及实机仍待验证。
