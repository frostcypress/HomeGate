# 已确认操作的原孤立工作目录收集

原型固定入口为 `account --collect-orphan original-job --confirm`。协调器、持久终态验证工具和收集工具的 `dns_orphan_collection_enabled=false` 均关闭，环境变量不能启用；生产配方不安装原型。此动作只处理原临时目录，不发送 DNS、不重试未知变更、不删除持久检查点或终态、不代替另行确认的回执归档。

## 授权边界

前端 FD6 和独立监督 FD7 的文件、权限、inode 及共锁均须核实。既有独立 watchdog/工作端在工作族未退出时保留共锁；收集入口不能绕过忙碌锁。另通过受限进程元数据确认原协调 PID 已退出；活动或复用 PID、读取失败或无法证明退出均拒绝，不向旧 PID/进程组发送信号。

调用固定 `orphan-check` 复用完整持久存储/当前配置代/原账户与工作编号校验，并验证原 HGCFJOURNAL1、HGCFTerminal1、所有 SHA 及规范成功报告。未知结果、部分计数、损坏证据、checkpoint 或 terminal 准备残留不能授权收集。只有终态文件已完整发布才继续；原临时成功观察不生成或补造持久成功结论。

原目录必须仍为同启动期的固定私有 `.dns-check-original-job`，0700、正确 UID；精确包含 `request/result/zones/state/input/context/attempt` 七个固定 0600 单链接普通文件，各有大小限制。`attempt` 精确匹配标记；`zones` 必须与已绑定的持久 `terminal` 字节相同。`input/context` 为规范 JSON，其请求、账户、配置代、资源范围、冻结删除集合、位置和已影响计数必须与原检查点一致，并处于对应的 verify-upsert/verify-delete 阶段。数据适配器使用当前私有快照验证，凭据仅在内存中读取。

原目录若在模拟新 boot 后仍存在，不能证明它属于旧启动期，拒绝删除；若已丢失则不重建、不按旧 PID 发送信号。其他孤立目录、原目录符号链接、未知文件/子目录、硬链接、权限或大小异常均保留并拒绝。校验全过程不打印域名、挑战值、请求头、凭据或工作内容。

## 中断与续做

删除前，在原持久 `dns-operation` 内写私有 `.orphan-plan`，验证并 fsync 后发布为 `orphan-plan`，再同步持久父目录。HGCFOrphan1 只记录插件/存储身份、原 boot、配置代、账户、工作编号、已验证 terminal-meta 的 SHA、原目录设备/inode、七个文件 SHA 和规范 LF 帧校验；不持久复制请求、Token、挑战值或原工作内容。

先完整检查所有剩余成员及目录身份，再逐一删除固定名称、每步同步原目录，最后删除空目录并同步运行目录。已经发布且绑定完整的计划允许成员因之前删除而缺失；剩余成员必须仍匹配原 SHA，不能跳过损坏或新增内容。尚未发布的准备计划只允许原七文件完整且重新验证时继续，不能据准备计划推断缺文件已被正确删除。重复/半截/损坏计划、身份或目录 inode 不符均保留屏障，不自动清理。

全部工作目录处理完成后才删除计划并同步。失败不报告收集成功；明确重做同一编号可按有效计划续做，包括目录已空、目录已消失、模拟 boot 改变且原临时目录已丢失等状态。最后计划删除的同步结果不确定时，活动持久回执仍在；重复操作重新验证终态与父目录后确认。没有计划且目录原本不存在时，只做终态校验与重同步，不生成新证据。

成功只返回 `orphan_collected=true, write_ready=false`。`dns-operation`、原检查点和终态字节始终保留；配置/DNS 写入继续受阻，之后须另行明确执行既有回执收集，再按其他屏障实际状态判断是否可写。计划尚在时普通回执收集拒绝，门禁关闭也不会自动忽略残留。

隔离专项使用实际 Linux/BusyBox/Lua/jsonc 与回环 HTTPS 夹具，覆盖拒绝、固定成员删除和中断续做；不构成实机断电、完整冷启动、生产生命周期、SDK/ABI 三包或资源验收。配套 r37 检查点恢复与本动作形成相关本地批次，工作流接入及集中 CI 状态以本地接续计划为准。
