# 已确认 DNS 归档的有界清理

隔离原型增加固定 `account --retire-archive numeric-original-job --confirm`。仅处理经完整 checkpoint、terminal、settled 收集凭据校验的旧 `dns-settled`。不清理未知结果、活动 `dns-operation`、配置代次、秘密或孤立临时工作，不进行网络调用；无有效归档或绑定不符时拒绝。未接入官方授权 LuCI、生产安装或实际设备。

`dns_retention_enabled=false` 与既有只读/记录/持久/终态门禁共同限制入口。环境变量不能启用；生产配方不安装原型。固定工具须持有同一前端 FD6 和监督 FD7 锁，入口保守拒绝任何临时孤立工作。

清理前建立固定 `HGCFRetire1` 计划，绑定存储身份、原账户/工作编号、收集凭据及全部允许归档文件的 SHA256。严格限制文件名、数量、大小、属主、目录/文件模式、单链接和完整规范帧；不存在的非活动槽以固定占位值表示，不接受外部路径。计划准备文件同步、重命名和父目录同步成功后，才把完整归档移入固定 `dns-retiring`。

先完整预检所有剩余文件，再逐项删除允许的槽文件、槽目录、指针和终态文件。每层删除/目录同步结果都必须成功；不使用递归删除或通配删除。保留活动回执原字节，即使它来自下一次操作。移除旧归档和匹配的旧收集凭据并同步父目录后，把计划原子转为 `dns-retired`，保留一份有界完成凭据。下次明确清理其他归档时才替换这份完成凭据；不会无限积累归档，也不会自动清理历史。

任何计划、准备残留或清理中目录的存在都会阻塞写入，不受功能门禁控制。持有同一完整计划时，明确重做相同账户/编号可在文件已部分删除、目录已删除、收集凭据已删除等阶段继续，逐项核对剩余文件；新增文件、链接、内容变化或计划损坏继续阻塞。准备残留、损坏计划和未知结果不自动修复。

最终计划重命名后的同步失败仍不能直接放行。每次后续写入验证完成凭据的规范帧及身份，并重新同步该文件与父目录；同步失败则继续阻塞。重复确认已经完成的旧编号不删除下一份归档，返回值不声称所有写入屏障已经解除。其他配置/服务屏障与活动 DNS 回执继续独立生效。

此阶段只解决已确认归档的容量回收及有计划的中断续做。不完整 checkpoint/terminal 的受控修复、未知写入归属确认、官方授权与审计页面、完整生产冷启动、SDK/ABI 三包、真实设备断电/重启和资源预算仍需后续完成。隔离故障注入不能代替实机证据。
