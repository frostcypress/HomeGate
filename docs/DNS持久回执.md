# DNS 变更前持久回执（r32）

在固定 Cloudflare 记录原型内新增受限持久检查点；所有入口仍不安装，`dns_receipt_enabled=false` 在协调器、独立监督器、工作端和检查点工具四处关闭，`dns_recovery_read_enabled=false` 关闭内部恢复只读命令。环境变量不能启用。r30/r31 无检查点的测试保持为历史对照；本阶段只有复制路径/UID/源码门禁的隔离回归启用新功能。

## 变更前顺序

数据驱动器在变更前保存同启动期 attempt/context，返回固定 HGDNSWRITE1；工作端收到后先调用固定 `homegate-dns-receipt.sh checkpoint account revision job`，成功返回后才调用固定 curl。GET 返回 NEXT，不生成持久检查点。不能由外部输入提供路径、方法、命令或 URL。

监督器仅在本检查点模式向工作端出借已持有的 FD6/7；检查点工具逐 inode/权限核对两把锁，再复用引擎的完整持久存储、全部代次、应用/恢复屏障验证。curl 显式关闭 FD6/7 及其他私有 FD；监督期限仍覆盖检查点与传输，生产总预算 30 秒，回归复制预算 8 秒。目标 QWRT fsync/setsid 选项仍待实测。

持久数据位于固定 `/etc/homegate/transactions/dns-operation`，0700 目录、0600 单链接普通文件，拒绝符号链接和未知条目。首次创建即同步存储父目录，未完成初始化也作为恢复屏障。检查点由两个固定 slot-1/slot-2、一个 current 指针组成，每槽只有 context/manifest；.prepare/.next 仅本次准备，残留直接拒绝，不自动清理。

先校验当前槽的完整绑定和 SHA，再校验/删除同一原操作的旧非当前槽并同步目录。新数据写到 .prepare，fsync context/manifest/准备目录，原子重命名到非当前槽并 fsync 回执目录；写 .next、fsync 指针文件、原子替换 current，最后 fsync 回执目录和存储父目录。全部返回成功后才能发 HTTP 变更。中途失败、同步结果不确定或 SIGKILL 保留目录和此前当前槽，不回退或重试变更；下一写入不能把残留解释为成功。

## 私有数据和绑定

复用真实记录上下文，只按固定白名单保存已校验原请求、AAAA 数值身份/TXT 挑战值、资源/范围/TTL、完整冻结删除 ID 集合、阶段/位置和已确认计数；Token、headers、transport URL、分页 ID 集合及未知字段不落入持久回执。TXT 值和域名仍是私有恢复数据，不能把整个目录放到日志/RPC/普通配置导出。

HGCFJOURNAL1 清单绑定 homegate、完整 HGSTORE1 身份文件 SHA256、boot、配置代次、账户、固定工作编号、该代 manifest SHA256、私有 context SHA256，尾部为规范 LF 帧的 SHA256。每次检查点验证这些字段和原调用一致；不能把其他存储、账户、代次或工作编号的槽接着用。最多两份 8 MiB 私有上下文和暂存一份；未取得目标设备峰值/闪存写放大预算，不开放生产。

current 的发布不会让旧槽先消失；第二/后续变更前检查点失败保留上一份当前证据。重复删除可交替使用两个槽，而非无限积累每次变更文件。最新证据表示最后一次变更发出前的计划；已确认最终计数和完整终态结算还未追加，不能用检查点推断远端最终结果。

## 持久屏障和恢复边界

持久引擎只要发现 dns-operation（包括不完整、损坏和悬空链接），就拒绝 writer-check、配置/凭据/预览/取消、应用事务及服务恢复/生命周期动作。该存在检查不受新功能门禁或环境变量控制，不删除回执；原生 17 个写处理器经同一 writer-check 受阻。旧 Go/实际生产写入口尚未全面迁移，不能称全部生产组件已完成共锁。

仅 status/export 与固定内部 dns-recovery-check/dns-recovery-snapshot-read 可继续，仍需其余存储/应用屏障通过；恢复检查明确返回 write_ready=false，私有快照只写继承管道。r31 同启动期确认只读核对可使用恢复读命令，核对不改持久回执、原 unknown 或 DNS 阻塞。

即使 DNS 变更报告已确认，也保留持久屏障；当前没有终态结算、官方授权收集、跨重启回执读取与冷启动业务恢复。丢失 /var/run 或模拟 boot 改变后，配置/DNS 仍拒绝写入；这只证明隔离文件系统的保守屏障，不能冒充设备重启/断电恢复通过。下一阶段必须完成这些恢复动作，再开放业务调度。
