# 检查点发布中断的明确恢复

固定原型入口为 `account --repair-checkpoint original-job --confirm`。协调器与内部工具的 `dns_checkpoint_repair_enabled=false` 均保持关闭，环境变量不能启用；原型不安装，也没有新增 LuCI/RPC 生产入口。

此动作只继续已有完整检查点的本地发布，不重发 DNS、不根据供应商观察生成成功结论、不结算或收集终态、不删除原孤立工作目录。返回 `checkpoint_repaired=true, write_ready=false`；`dns-operation` 及原孤立证据继续阻塞写入，后续只读核对、终态修复和收集各走其独立条件。

## 允许的状态

- 首次检查点尚未产生 `current`：必须有原协议留下的私有 `.next`，并且仅有完整 `.prepare` 或 `slot-1` 候选；不能有 `slot-2` 或重复候选。`.prepare` 仍在时 `.next` 必须为空；`slot-1` 已发布时 `.next` 可为空或严格为 `1\n`。候选的已影响计数必须为零。此路径只完成原首次发布，不能用来恢复丢失的历史指针。
- 已有合法 `current`，同时有 `.next`：完整候选只能位于非当前槽或唯一 `.prepare`；`.next` 为空或精确指向非当前槽。仅允许同一冻结删除请求的前进检查点，位置严格增加、已影响计数不倒退且增量不超过位置增量。账户、原工作编号、原 boot、代次、原请求、冻结 ID 集合和其他上下文字段均保持一致，不能换请求或回退到旧槽。
- 已发布 `current`，无 `.prepare/.next`：验证当前及所有存在的槽，重新同步当前指针和证据，允许明确重做最终同步；不选择另一个槽替换当前。

每个槽均需原 0700/0600、UID、单链接普通文件、固定文件集合、大小及 HGCFJOURNAL1 规范帧/SHA 校验。候选与原当前上下文还必须是规范 JSON、只含持久白名单字段，并通过当前私有配置快照的资源/代次/请求绑定验证。原 boot 可以与现在不同，但所有证据必须属于同一原 boot。当前配置代和存储身份必须仍匹配。

## 发布顺序与拒绝

沿用前端 FD6、独立监督 FD7 共锁并逐 inode 验证，复用持久引擎的完整存储/代次/应用屏障检查。全部证据及前进关系校验后，重新 fsync 各槽文件/目录与父目录；若候选还在 `.prepare`，仅重命名到缺失的非当前槽并同步目录。已有空 `.next` 填入唯一目标，fsync 后原子发布 `current`，最后同步指针、回执目录和存储父目录。保留之前当前槽的字节，不递归删除或清理未知证据。

任一步骤失败不报告修复完成，写屏障保留；重试仍须显式确认并重新校验实际状态。发布槽后或指针后同步失败，可在原证据完整时继续。半截 `.next`、损坏/缺失清单或上下文、损坏当前槽/指针、缺指针但已有双槽历史、重复候选、未知条目、链接/权限异常以及终态文件混入均拒绝，保留原样。没有完整候选的 `.prepare` 不会被自动补造或丢弃。

原私有 `.dns-check-original-job` 仅允许保留在原处；其他孤立目录、原目录的符号链接或权限异常仍阻塞。恢复入口不读取临时请求或成功报告来重建持久证据。错误工作编号在原孤立目录仍在时先按忙碌拒绝，目录已丢失时再由持久身份绑定拒绝。

隔离专项使用实际 BusyBox/Lua/jsonc/curl 与可丢弃回环 HTTPS 数据库，验证发布中断、旧证据保留、拒绝状态和不产生新 HTTP 请求；模拟 boot/临时目录丢失不是实机断电验证。此阶段不代表完整冷启动、业务迁移、目标 SDK/ABI、三包或实机资源验收。
