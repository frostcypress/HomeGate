# 中断终态发布的明确确认恢复

隔离原型增加固定 `account --repair-terminal original-job --confirm`。它只继续已经存在、能够完整验证的终态证据对，不调用供应商、不从当前观察或临时工作结果重建终态，不解除活动 DNS 写入屏障。新增 `dns_terminal_repair_enabled=false` 及既有门禁共同限制入口，环境变量不能启用，生产配方不安装原型。

同一前端 FD6、监督 FD7 锁和真实持久命名空间检查通过后，要求原账户、工作编号、当前配置代次、存储身份、原 boot 和代 manifest/检查点 SHA 全部绑定。当前指针和两个检查点槽必须原本有效，不能从较旧槽推断指针或回滚。允许原 boot 不同，但这不代表已经完成设备冷启动验收。

终态报告和绑定清单各有两个固定候选名：`terminal` / `.terminal`，`terminal-meta` / `.terminal-meta`。每类必须恰好一个；已发布/准备文件混合状态可恢复，重复副本即使相同也拒绝。缺少任一文件、超限、错误权限、符号/硬链接、额外文件或 checkpoint 准备残留均保留原字节并拒绝，不自动删除或补造证据。

先验证完整 `HGCFTerminal1` 帧、所有 SHA 和 canonical 成功报告；报告必须仍满足原操作类型、最后检查点、账户/代次和精确变更计数。未知观察、部分删除计数、重复 JSON 字段或重新拼接的错误报告不能作为已确认终态。两个候选文件及目录重新同步成功后，才分别发布尚未发布的文件；发布后再次校验和同步。任一步失败均保留现有候选，后续明确确认重做相同编号可继续；已发布的完整证据对可幂等重同步。

原工作编号对应的受限临时目录可存在，但本入口不读写或删除它；其他孤立工作阻塞恢复。成功返回 `terminal_repaired=true`、`write_ready=false`，活动 `dns-operation` 始终保留，原临时孤立工作也继续阻塞后续收集。只有满足既有收集条件并另行明确确认后才能归档；本入口不等同于清理孤立工作、完整业务恢复或放行写入。

本阶段仅覆盖完整终态证据对的中断发布。不完整 checkpoint、指针/准备残留、损坏或缺失证据、未知远程写入归属仍需后续受控处理，不能自动结算、重试或丢弃。官方授权 LuCI、生产冷启动/生命周期、SDK ABI 三包、真实设备异常与资源验收仍未完成。隔离故障注入和模拟 boot 变化不作为实机证据。
