# LuCI 与 Shell DDNS 授权链路验证

`scripts/luci-ddns-authority-regressions.py` 复用固定宿主真实 Lua LuCI、uhttpd、rpcd 会话、nixio 私有传输和 r85 的普通配置初始化，验证 POST/CSRF 到真实 Shell 授权预览、确认、撤销及状态的完整候选链路。入口为 `scripts/check-ddns-authority.sh`，与 RPC 授权一起归入现有 DDNS 原生授权 UI 专项 CI 组，生产配方和原有关闭门禁保持不变。

八个独立场景覆盖：单条许可的预览/确认/撤销及状态；规范多规则集合与窄化替换；真实 CSRF、POST 和明确同意/输入策略；确认替换和重放拒绝；源配置漂移/不安全权限；真实公共/监督锁忙及不安全预览文件；重新关闭模型或 Shell 门禁；私有凭据变化。失败逐次比较全部私有配置、状态字节及权限/inode/链接数，不能替换或删除已有许可/预览来制造通过。

授权辅助门禁开启后，四规则真实状态读取本地实测约7–10秒。原宿主夹具用于门禁拒绝路径的6秒时限不足；本专项采用冻结合同原有的18秒读取上限，同时设置有限HTTP/CGI时限，其他专项仍默认6秒。未修改产品超时。八项按授权范围/拒绝屏障分成两个独立私有namespace，分别沿用原有90秒整组上限，不删用例、不放宽锁或协议校验。

仅临时副本开启授权相关开关，执行真实授权文件的原子发布；不改固定路径、root 检查、锁或校验协议。外层非 root 映射到私有 UID0，capabilities 全零；源码及运行时只读，只有夹具自有配置/事务目录可写。请求实测0700/0600并清理；返回及诊断不打印随机会话/token、确认码、凭据或私有快照。每个用例结束只清理自身新增的授权记录，再核对其他配置/状态完全不变。

服务观察仍为初始化所需“停用/无实例”夹具；授权操作不启动服务、不调用供应商、不执行任务、不采样地址。curl/wget 检出工具不得被调用，规则状态的 ready 只代表已许可且无等待，不代表 DNS 已更新。真实任务提交/维护、JS/RPC 写入、生产接管、目标 LuCI/SDK/ABI、三包、设备异常与资源仍须分别验收。本地及集中 CI 的实际结果以独立证据记录为准，文档存在不表示测试已经通过。

为避免已耗时约22分半的源码组继续累积，r90将两个授权宿主专项移至现有DDNS原生授权UI矩阵组，保留原页面专项并补齐同一固定运行时与隔离前置；源码组保留原会话/只读检查。没有删除检查、增加自动CI或调整25分钟job上限。
