### 用户操作

1. 源码ZIP解压，根内容含.github完整推到仓库；普通push先验证，产物只在Actions。
2. Actions选择“HomeGate 构建、验证与发布”→Run workflow，release_format选IPK/APK/两者；publish_release勾选才发布。工作流必须已在默认分支，GitHub才显示手动入口。
3. 全部构建通过且发布job通过后，Releases打开v1.3.0-10；下载匹配实际架构的一份homegate核心+同格式luci-app+中文包，共三包；另下载相应SHA表和安装说明。
4. ARM64有效架构识别合同不变（APK核对/etc/apk/arch，不只看--print-arch）。需要自动安装和完整验收时再下载Actions大包。

### 4.3 访问限制、数据源与海外访问

- 用户接受三个四字选项：**不限地区／仅限名单／中国地区**。省份模式已移除；历史 CN-* 迁移为仅限名单并保留 enabled/allow/deny，页面提示重选并保存，不自动扩大成全国或不限制。导入配置同样处理；空名单拒绝全部，显式 deny 优先。
- 中国数据主源 APNIC 官方每日分配统计，备用 RIPE 官方镜像；解析 CN allocated/assigned 的 IPv4/IPv6，验证完整记录计数、分类汇总、CIDR/范围及大小上限，原子写入 0600 缓存，有效期 7 天。刷新失败保留已验证旧缓存；没有可用缓存就拒绝启用中国模式，不降级成不限地区。
- CN 是资源登记归属，不等于客户端当前物理位置；HK/MO/TW 不并入 CN。官方源也不保证地理定位精度或永久可用；不内置固定数据库，首次中国模式需要联网。

| action_wol | 先wol_interfaces，再wol_client_candidates；两者都调用lan_interface_inventory | 同次请求复用接口快照，减少重复枚举，核对桥接/接口过滤不变化 |
| wol_client_candidates | 同步读本机MAC、ARP、ip neigh、bridge fdb、DHCP等 | 页面必需的已配置主机与候选发现区分；考虑候选延迟获取/短期缓存，但保留LAN过滤、MAC校验、接口一致性和刷新机会 |
| basic模板加载后 | 再分别请求status和network，显示Loading状态 | 测量页面可见与状态可用两个时间；无IPv6/AP/慢网络也要有界等待，不阻塞其他控件 |
| transport异步写入 | 现有任务轮询有500ms间隔 | 是写动作链，尚不能解释只读页面切换；只有证据显示影响体验才改，保持一次提交、超时、结果确认/ack与重试安全 |

这些是优化候选，不是已证明的实机瓶颈。源码导航：

- 原始控制器：`package/luci-app-homegate/luasrc/controller/homegate.lua`。
- 原生入口：`package/luci-app-homegate/htdocs/luci-static/resources/view/homegate/`。
- 原生transport：`package/luci-app-homegate/htdocs/luci-static/resources/homegate/transport.js`。
- 原生共享规则/host适配：`core/internal/frontend/engine.go`、`host_linux.go`。
- 修改原模板/控制器后运行`scripts/sync-frontend.py`、`scripts/build-js-views.py`；不要只改生成副本。

### 测量方案

1. 建立四页面所有12个有方向的切换矩阵，不只比较两条路径；区分首次冷加载、重复暖加载、手机/桌面及无IPv6的AP环境。
2. 记录点击到首屏可交互、点击到状态更新完成、请求数量/总字节、RPC响应、后端耗时与子进程次数；浏览器performance/Resource Timing与后端阶段计时配对。
3. 固定设备/固件/主题/浏览器/网络条件；暖加载每路径至少10次，保存样本数、中位数、p95、最大值；冷加载注明缓存状态，不能混进暖加载平均值。截图版本、安装版本与源码版本必须一致。
4. 标记静态模块加载、RPC队列、Go启动/规则引擎、UCI读取、包查询、接口/邻居扫描、DOM渲染和加载后状态刷新。计时不得输出凭据、私钥或完整请求表单。
5. 无设备时用可控延迟fixture验证异步逻辑，并将真实毫秒改善列为待验收。不能通过隐藏Loading、取消数据获取、偷偷扩大超时或拿PC结果冒充ARM路由器加速。

### 优先实施次序

1. 合并同次请求重复工作，减少不必要子进程、重复解析、序列读取；这是比跨请求缓存更容易保持正确性的第一步。
2. 让慢的非关键数据不挡主表单首屏；明确Loading/错误/重试，不改既有布局。请求失败不清空用户已配置数据。
3. 对稳定元信息和安全只读数据评估有限TTL缓存/请求合并；写入成功、安装升级、配置导入/恢复、接口变化时失效。状态/配置不能因缓存掩盖真实变化；凭据/权限敏感结果不共享缓存。
4. 再评估脚本体积与解析、DOM更新/事件数量。只有测量显示有意义才考虑导航方式或模块拆分，不能直接把现有页面重写成SPA。

## 4. 其他收尾审计清单

| 项目 | 重点 | 必须守住的行为 |
|---|---|---|
| 页面切换与异步生命周期 | 重复定时器、监听器、observer；旧页面响应覆盖新页面；快速来回导航 | 离开页安全取消/忽略响应，不中断已提交业务任务、不泄漏状态 |
| 保存/上传反馈 | 无谓串行RPC、重复提交、轮询等待、错误不显示、超时后重复执行 | CSRF/ACL、字段验证、一次执行、结果确认、草稿与文件不丢 |
| DNS/证书交互 | 域名列表请求合并、重复获取、旧账户响应、网络失败/慢服务商 | 切账户不串结果；凭据不落日志；真实DNS/ACME不因UI测量被调用 |
| 维护日志/诊断 | 多余全量读取、重复解析、刷新重叠、增长内存 | raw日志合同、最新响应保护、大小限制；不重新引入Time View |
| 大配置渲染 | 多服务/名单/主机、长域名、移动端DOM/布局抖动 | 默认布局不变、转义/XSS防护、列表与草稿一致、按钮可操作 |
| 核心后台 | 重复配置解析/文件读写、轮询周期、锁范围、goroutine/FD释放 | 原子保存/备份、请求取消、证书身份、日志不丢、权限及fail-closed |
| 访问限制 | 数据更新/缓存、更新失败、安全旧缓存、显式deny优先 | 三选项不变、不自动放宽；无有效中国缓存不能变不限地区 |
| 冗余清理 | 同功能重复实现、无调用代码、无效分支/重复CSS | 先追踪调用和生成来源；不要删除兼容分支、许可证或覆盖边界的测试 |
| 打包与安装 | 四ARM64 profile、noarch/all、三包版本、升级/卸载、缓存刷新 | 不用--print-arch单独判断；不强制架构；升级保留状态，真卸载FULL PURGE |
| 文档/交付 | 生成副本、源码ZIP和工作流、累计验证账本 | 实测/模拟/历史分开，检查哈希与独立解包，不依赖旧目录 |

各项按“已有问题→证据→风险→修改→验证”处理，没有收益证据的复杂改造可以保留为未实施建议。不要为了优化清单长而挨个大改。
