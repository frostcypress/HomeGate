# 原生 Lua 写入协调（阶段草稿）

1.3.0-r23 将 17 个会改变配置或运行状态的原生 Lua 处理器包入固定协调入口。包围整个处理器，从创建 UCI 游标之前开始，直到保存、调用核心或应用、返回结果为止。导出、导入预览和诊断下载这三个只读 POST 保持直接运行；42 条原有路由、鉴权和业务校验不改变。

不能将 `nixio.File:lock()` 当作原有 `flock` 的替代：OpenWrt 21.02 [官方 nixio 实现](https://github.com/openwrt/luci/blob/openwrt-21.02/libs/luci-lib-nixio/src/file.c) 调用 `lockf`。新 Shell 入口使用原有 `/var/run/homegate/frontend.lock` 的非阻塞 `flock`，在创建游标或运行处理器之前取得锁；锁已忙或路径不安全时拒绝，不修改锁文件权限、不删除或替换活锁。现有 Go 对照桥接已经在 `Begin` 中取锁，只在其已授权的同一路由内调用原处理器，不再次转入原生传输或重复取锁。

原生传输只允许固定路由和字符串字段。JSON 保存到内核 UUID 派生的独占 0700 临时目录及 0600 文件；命令只接收内部派生的十六进制路径，凭据不会成为命令参数。正常、短写和异常路径关闭文件并清理本次请求。Shell 检查类型、权限、单链接、大小及锁 FD 与固定路径身份；Lua 使用官方 jsonc 严格结束判断、字段校验与固定 17 路由表，不接受任意处理器、命令、执行文件或路径。Lua 持有继承的锁；同步核心命令先在启动 Shell 自身执行 `exec 6>&-`，然后运行命令，避免等待命令的 Shell 与子服务继承写锁。原始 JSON 的真实 NUL 转义在解码前拒绝，防止旧 jsonc 截短后接受；转义后的字面反斜杠仍可用。返回范围限于本插件四个页面的有界跳转；操作失败跳转含 `error` 时 `ok=false`，传输完成不代表应用成功。

本轮还把直接 UCI 提交收敛为一个函数，要求明确成功；WOL 提交失败时不再发送唤醒包。配置游标是在锁内读取，因此不同网页请求不能使用同时取得的旧基线相互覆盖。保护范围仅覆盖列出的 Web 处理器及现有桥接写入，系统管理员直接修改文件或其他生命周期入口仍需后续协调。

新增 8 项本地静态/传输及 12 项 Linux 用例，另运行对照 Go 桥接的现有测试及两项协调测试。Linux 结果待当前 Actions。Linux 夹具使用真实 BusyBox、Lua51、官方 jsonc、文件和 flock；UCI、核心与服务调用是明确的隔离夹具，未操作路由器或执行真实服务命令。

**原生写入和发布两个生产门禁仍固定关闭。** 原生协调未启用；用户手上的已安装版本不会受源码改动影响。本阶段若绕过正式构建门禁而单独复制新 Lua Controller，写操作会返回 503；不得这样安装。原型 Shell/Lua runner 未安装进包。关闭门禁是因为持久命名空间/应用日志屏障、来源及秘密迁移、请求工作端独立期限、异常期间业务静止与恢复、冷启动尚未接入；不能把锁释放测试视为业务已经恢复。所有完整 Shell/C 业务、SDK/ABI/三包与设备验收仍待完成。

Linux 首轮发现旧 jsonc 的 NUL 截短和子 Shell 锁继承问题，已修正输入检查、启动 Shell 关闭位置；中断测试只允许最多 2 秒的临时锁忙调度窗口，持续继承仍失败。失败记录保留在本地。

详细验证记录、当前三份接续 MD 和完整接续 ZIP 只保存在本地。
