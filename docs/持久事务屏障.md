# 固定持久命名空间与写入屏障（阶段草稿）

1.3.0-r24 在隔离事务引擎中增加固定 `--persistent` 模式：仅使用 `/etc/homegate/transactions`，不接受请求或环境选择目录。0700 私有父目录、0600 单链接身份文件、两把既有私有锁和共享写锁必须由后续迁移/生命周期建立；本模式不创建目录、不补锁、不初始化生产基线、不修改现有目录权限。身份格式 HGSTORE1 绑定插件、六类公共 schema、固定路径和存储身份，按严格行数、内容及 SHA256 核对；摘要是完整性校验，不是 MAC。

共享 `/var/run/homegate/frontend.lock` 在监督锁与配置锁之前取得，已继承的同一路径 FD6 保留使用。所有持久事务操作参与该锁；原生 Shell 写入口在保持 FD6 的情况下调用固定 `config-transaction --persistent writer-check`，只有检查通过才载入 Lua Controller 或 UCI 游标。检查与处理器之间由同一 FD6 排除其他持久写事务。旧原生测试明确使用无操作屏障夹具；本阶段的新用例使用实际复制的事务引擎。

每次应用先同步已封存候选，再同步、原子发布 HGWRITEFENCE1 活动凭据，随后创建应用日志。凭据绑定存储身份、基线、候选和内部句柄。`writer-check` 输出不包含该凭据、存储身份、原始配置或密钥；恢复句柄仍沿用既有内部确认接口，不能当作公开 Web 参数。凭据或日志不匹配、损坏、遗失、路径不安全，或者遗留临时文件/不完整代次时拒绝写入，不自动删除可疑状态。活应用日志、工作记录及活动凭据持续阻止原生入口。

应用/恢复确认必须先进入终态、删除预览并同步、删除应用日志并同步，然后原子写入 `settled-applied` 或 `settled-restored` 凭据。活动凭据不直接删除，所以日志删除后的同步失败仍留下屏障。最后一次凭据发布若目录同步失败，后续写入检查必须重新成功同步已完成凭据及目录后才能放行；此前的日志删除和应用确认已经完成，不能跳过这条顺序。日志缺失而凭据仍活动时，要求后续专门的受监督协调，普通恢复命令也不能猜测完成。

每次检查核对所有有界历史代次及当前指针。跨进程重新打开存储不移除屏障；HGAPPLICATION2/3 绑定的启动身份变化继续拒绝成功确认。只允许明确内部恢复接口在活日志下进行既有恢复流程，普通网页请求不能通过传参或环境清除、忽略凭据。启动身份变化用读取夹具模拟，没有声称真实重启或断电通过。

新增 3 项静态检查和 21 项 Linux 用例。21 项 Linux 屏障、对照 Go 及全部既有回归通过[Actions](https://github.com/frostcypress/HomeGate/actions/runs/38338971798)；实际源码 `d544846f3f91840e0bbfcb125ff0dde51ad0e3fc`，51 个关键文件逐字节核对，SDK/发布跳过。真实 BusyBox 1.33.2、Lua51/jsonc、文件、flock、fsync、rename 和 SIGKILL 用于私有复制夹具；路径、UID、固定门禁及 boot 文件读取在测试副本替换，身份和已建立基线由测试程序创建。UCI/业务命令仍为隔离夹具，没有写路由器、真实服务或闪存。

**持久、原生写入及发布生产门禁均固定关闭，原型未安装。** 本阶段只完成屏障接入草稿；生产迁移所有者、受监督独立期限、日志缺失凭据活动时的业务协调、冷启动/掉电、Go 对照及其他生命周期写入口、真实核心业务、SDK/ABI/三包与目标设备/资源仍未完成。原生处理器尚未把全部 UCI 修改映射到私有代次，不能单独复制安装 Controller 或打开门禁。
