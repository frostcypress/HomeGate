# 持久独立监督与孤立凭据恢复（阶段草稿）

1.3.0-r26 复用既有监督器、独立会话看门进程和私有快照，增加固定 `--persistent` 模式与 HGWORKER2 工作记录；不新增 Web 执行接口。存储固定 `/etc/homegate/transactions`，初始化入口提前建立私有 `.recovery.lock`，监督器不补锁、不建目录。持久监督、工作端、孤立恢复及既有生产门禁均固定关闭，生产配方不安装原型。

持久模式清除路径、Lua 和期限相关环境变量，固定实验期限 30 秒；上线资源预算尚未冻结。记录绑定 HGSTORE1 存储身份、路径、当前启动身份、PID/出生时间、角色、内部句柄与期限，并核对原始字节。新工作在共享 FD6 内保持授权、快照、工作族静默核实和最终 ACK；FIFO 使用 FD4，工作端关闭 FD6/7，生产端和独立看门进程保留协调锁。外层进程退出后，独立期限仍停止自己的进程组，原生网页仍被共享锁或应用屏障阻止。

恢复首先在专用恢复锁内确认旧工作族静默；旧族可能仍占有 FD6，因此停止请求与静默核实先于取得共享写锁。只请求已核对身份、出生时间、会话及句柄的原看门进程停止自己的组，不向持久记录中的 PID 发信号。无法确认静默、双重强杀仍有可执行子进程、身份不匹配或旧 boot 均保留记录与屏障。未使用 cgroup/subreaper，不能约束任意第三方后台化或声称完成真实冷启动恢复。

每次持久应用在活动 HGWRITEFENCE1 之前，同步发布 `application-anchor` 及 HGRECOVERY1 绑定元数据。锚点是原始 prepared 日志，保留 HGAPPLICATION1/2/3 格式、完整代次绑定与服务意图；绑定存储身份、同一 boot 和原始字节摘要，不包含原始配置/凭据。只保留上一笔锚点，文件有界、0600，摘要不是防 root 修改的 MAC。

内部 `recover-fence` 仅接受无参数持久调用。只能在日志缺失、活动凭据与同 boot 锚点匹配、代次/祖先/清单与原意图全部可校验且无工作记录时，重建 restoring 日志并恢复基线指针；仍需受监督工作端的恢复 ACK，不能直接解除屏障。已有损坏日志不会被锚点覆盖，旧格式无锚点、损坏/外来/旧 boot 锚点拒绝自动恢复。已完成日志删除而凭据仍活动时，保守恢复原基线，不猜测已经成功；此阶段没有远端 DNS/ACME 副作用撤销功能。

持久工作授权、快照、ACK 和现有日志恢复也检查同 boot 锚点，避免 HGAPPLICATION1 缺少服务意图字段时绕过启动身份核对。当前工作端仍仅生成隔离公共派生回执；HGAPPLICATION2 服务意图恢复验证格式保留并拒绝回执工作端确认，HGAPPLICATION3 的真实预检、启停和观察恢复未接入。本阶段不声称任何实际 DNS、ACME、代理、防火墙或目标服务恢复。

新增 4 项本地检查与 23 项 Linux 用例：成功/失败回执、二进制私有管道、超时、TERM/SIGKILL、共享原生屏障、双重强杀失败关闭、活动凭据到日志之间异常退出、孤立凭据恢复、服务意图保留、坏日志不覆盖、锚点损坏/缺失/硬链接/外来身份/旧 boot、门禁与环境注入、缺锁不补、假成功拒绝、锚点/租约同步失败、任意命令拒绝、外来/旧 boot 记录不触碰无关进程。Linux 结果待当前 Actions。

测试仅在私有复制目录中替换固定路径、UID、源码门禁、boot 文件和实验期限（2 秒），使用真实 ash/flock/fsync/FIFO/setsid/信号及 Lua51；业务仍为回执/UCI 夹具。SDK/ABI、完整 Shell/C 业务、旧配置/秘密迁移、真实冷启动/闪存掉电、生产生命周期与资源峰值待完成，没有安装三包。

详细验证记录、当前三份接续 MD 和完整草稿 ZIP 仅本地保存；公开仓库只同步源码、协议与概述。
