# 配置应用与失败恢复协调合同

1.3.0-r18 在同一隔离 Shell 引擎中增加应用日志与工作端确认协议。日志、锁、文件、管道和进程中断由真实 Linux 回归验证；测试中的工作端结果由显式 ACK 代替，未运行 DNS、ACME、代理、防火墙或服务 reload。生产配方未安装该引擎，旧 UCI 与旧核心未切换。本合同不等于实际业务恢复或重启/断电验收。

## 提交和工作端确认

`--public-uci commit-apply <预览句柄>` 沿用已有五分钟、基线/存储/启动/候选绑定的预览检查，构建并同步完整新代次；随后先原子写入并同步 `application` 日志的 prepared 状态，再切换并同步 current，最后写入 applying 状态。返回新生成的私有工作端句柄，明确 `business_applied=false`。普通 `commit` 保留隔离存储回归用途，不连接生产服务。

日志包含固定格式、基线/目标代次、32 字节十六进制句柄、状态、两个代次清单与存储路径的绑定摘要；文件 0600、目录 0700。拒绝额外行、无终止换行、未知状态、错代次/祖先、符号/硬链接、完整性变化和复制到其他存储路径的日志。摘要与句柄不进入 status、备份或公共预览；这不是抵御 root 修改文件的 MAC 或认证协议。

日志存在时，预览/提交/迁移/凭据/取消等写入及普通业务 `snapshot-read` 返回 busy。status 只返回是否待完成及阶段；export 仍可用于公共诊断。授权工作端用 `apply-snapshot-read <工作句柄>` 从继承的 FD 3 私有管道读取日志绑定的当前新代次；只有 applying 且 current 指向目标时允许。此接口和下述 ACK 只供可信内部协调器，未增加 Web 路由。

`apply-finish <工作句柄> success` 代表工作端已经完成完整应用，并由监督器确认退出结果；先持久登记 applied，再清除并同步旧预览，最后清除并同步日志。成功确认不能重放。仅仅发布配置不会自动返回业务成功。

`apply-finish <工作句柄> failure` 先登记 restoring，再原子恢复基线指针，返回 `business_restored=false`。恢复不是完整结束：工作端用 `restore-snapshot-read <句柄>` 读取原代次及对应秘密，重新应用原业务意图；`restore-finish <句柄> success` 才能登记 restored、清除旧预览和日志并解除屏障。报告 failure 保持屏障并返回退出码 7；旧应用端的迟到 ACK 因阶段不匹配被拒绝。

## 中断和再次恢复

`recover-application` 不分配新代次。prepared/applying/restoring 统一保守恢复基线指针并要求工作端恢复 ACK。若 applied/restored 已经写入但删除日志失败，则验证对应指针后只重试收尾，不反向覆盖已经确认的配置。历史容量已满也可执行恢复。

日志首次 rename 可见后，即使目录 fsync 或之后发布失败，清理也必须保留其引用的候选。进程在指针发布前/后、applying 日志 rename 后被 SIGKILL，下一次命令仍能识别日志并恢复。发布后目录同步不确定仍返回既有退出码 6；日志或恢复过程不确定返回 7，不能当作成功后重新提交。终端日志清除前先同步删除旧预览，防止恢复到原基线后重放旧确认句柄。

本原型没有自动启动恢复服务、工作进程 PID/代次监督或超时强杀。生产监督器必须在恢复前停止并等待未完成工作端，防止旧工作端迟到修改派生状态；必须在全部读取/写入端遵守同一 flock 后切换生产目录。当前原生 Lua/Go 写入口仍未共锁，不能使用此协议直接覆盖 `/etc/config/homegate`。

当前日志只绑定配置与凭据代次，尚未捕获独立的开机启用和实际运行意图。生产服务预检必须将这些基线状态纳入受限日志绑定，并验证启动/停止/恢复顺序，不能仅把恢复配置指针当作服务已恢复。

协调器不尝试撤销远端 DNS 删除、重发 WOL 或覆盖独立续期产生的整个证书树。ACME 账户/私钥树的迁移、实际服务预检/应用/恢复和网络异常合同仍需业务实现。损坏日志或基线/候选无法验证时失败关闭，不自动猜测和删除；受限人工修复/隔离工具尚未完成。

## 回归边界

新增 15 项 Linux 检查覆盖成功 ACK/私有快照绑定、应用失败及恢复失败、所有写入屏障、错误句柄/阶段、候选与日志同步失败、发布后同步不确定、三个 SIGKILL 位置、终端日志清理失败、恢复文件与目录同步失败、并发 ACK/重放、容量满时恢复、日志格式/链接/完整性/存储复制。每次命令均为独立 BusyBox ash 进程，真实 flock/文件/fsync/pipe；只有业务执行端使用显式 ACK 夹具。执行结果待当前 Actions。

`/tmp` 隔离存储不承诺重启持久性，主机文件系统 fsync 回归不等于目标 flash 掉电测试；目标设备、SDK/ABI、三包和资源峰值仍未验收。详细记录、当前三份接续 MD 与本地 ZIP 不上传公开仓库。
