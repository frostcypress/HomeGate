# HomeGate V2.0 规范迁移设计

日期：2026-10-11（Asia/Shanghai）。输入：HomeGate 1.3.0-10 最终归档与同目录开发规范。名称沿用用户本次指定的 HomeGate / homegate；不重新命名，不增加公网 IPv4 产品功能。

## 需求基线

保留四家 DNS（Aliyun、Cloudflare、DNSPod、Huawei Cloud）的认证、域名发现、AAAA DDNS、记录删除；保留 Let's Encrypt 正式/测试、DNS-01、账户持久化、续期、本地证书校验；保留 HTTPS 反向代理、可信转发头重建、访问名单/中国数据、访问记录、IPv6 防火墙生命周期与冷启动恢复；保留 raw Ethernet + UDP WOL、LAN 桥成员解析、配置事务、日志限制、升级/重装数据保留和用户确认的真实卸载 FULL PURGE 合同。

现有 Go 核心内嵌 Lua 5.1 前端规则，DNS、ACME、代理、配置和调度均有业务逻辑；不得用只实现 WOL/状态的新核心替换完整产品。

## 核心选型待核实

方案 A 使用 BusyBox ash 控制低频任务，复用目标上可用的 nginx、成熟 ACME/DNS 工具；JSON/配置解析可使用官方 ucode/jshn。必须比较新增依赖、进程数量、HTTPS 代理峰值内存、四家服务商支持和升级兼容性，不能仅按脚本文件大小判断轻量。

方案 B 使用 C 核心，优先复用 libubox/uloop、libuci、成熟 TLS/HTTP 库；Shell 只辅助生命周期。需先用方案 A 原型证明实际性能或依赖预算不满足要求，再冻结方案 B。现有服务有持续 HTTPS 代理、信号/调度/证书状态，B 是需比较的候选，并非已批准或实测完成的技术基线。

用户已提供 Zyxel NBG7815 的 QWRT 两份目标报告，先按 Lua LuCI + IPK 适配，并允许 ImmortalWrt 21.02 或尝试 24.10 SDK。型号、musl 1.1.24/loader、OpenSSL 1.1.1x 与 67 个依赖版本已登记；实际 SDK 的库符号兼容、复用组件功能和峰值资源仍待核实，无法冻结 A/B、TLS 库、具体 SDK 与资源预算。详见目标兼容性报告.md 和 Shell原型方案.md。保留完整对照实现，不引入空壳 C 模块，不擅自宣称选型已完成。设备上 1.3.1-1 优化版按用户说明作废，以 1.3.0-10 为基线，无需立即降级。

## 后续迁移关口

1. 核实目标报告与真实 SDK；验证依赖，测量现有核心及 Shell 原型的峰值 RSS、常驻 CPU、DNS/续期/WOL 延迟。记录原始条件和误差。
2. 冻结 A/B 与完整 CLI/RPC/UCI 合同。最终包名为 homegate-core，程序保留 /usr/bin/homegate 兼容入口，内部实现归 /usr/libexec/homegate；明确旧包替换、冲突、升级中止恢复、FULL PURGE 及密钥迁移。
3. 逐项迁移配置/状态/锁、网络/WOL、DNS/ACME、访问控制、防火墙、代理和调度。所有业务完成前不替换生产核心。
4. 秘密移入 0700/0600 受限路径。导入采用 slug/格式版本/schema 校验、服务端预览、一次性确认、持久备份、原子写入和显式恢复；秘密缺失时不得自动启用。
5. 把公网页中 DNS、证书、代理/访问管理拆成独立设置页面。当前仅完成顶层三导航和设置分支，业务级拆页未完成。把历史主题兼容 CSS 收敛到官方组件与插件作用域，实测 360/768/1280px 浅深色。
6. 匹配 SDK 构建三个真实包；查控制元数据、架构、依赖、版本、源提交/run 和 SHA。工具不支持解码格式时失败，不仅凭文件名通过。
7. 实机验收安装、升级/重装、卸载、网络异常、权限、资源和全部公网功能；若采用常驻 C 服务增加 72 小时稳定性。仅通过 CI 不得标实机通过。
8. 完成发布程序、证据检查和 GitHub 发布审批 Environment；将当前禁止发布的步骤替换为经验证的正式/预发布流程。
